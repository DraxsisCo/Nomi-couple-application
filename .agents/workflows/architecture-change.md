# Architecture Change Workflow

## Route
Solution Architect → Domain Architect(s) → Product/Business owner when tradeoff affects scope → Engineers → QA/Security/Performance as triggered → Tech Lead

## Steps
1. State problem and current constraint.
2. Document current architecture and invariant.
3. Compare realistic options including doing less.
4. Record ADR for durable decision.
5. Plan incremental migration.
6. Implement in reviewable stages.
7. Validate compatibility and rollback.
8. Remove temporary compatibility layers only after evidence they are no longer required.
