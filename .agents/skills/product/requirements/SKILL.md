# Requirements

## Purpose

Turn an outcome into explicit product requirements.

## Procedure

1. State problem/user.
2. Define desired behavior.
3. Define permissions and failure states.
4. Define non-goals.
5. Define measurable result where possible.

## Guardrails

- Avoid implementation detail unless it is a true constraint.

## Output

Return:
- result
- evidence
- risks
- required follow-up
