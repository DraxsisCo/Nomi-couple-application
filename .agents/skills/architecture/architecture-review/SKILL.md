# Architecture Review

## Purpose

Review a proposed technical change for boundaries, complexity, and compatibility.

## Procedure

1. Map affected components.
2. Identify invariants and trust boundaries.
3. Compare with current architecture.
4. Assess data/API compatibility.
5. Recommend the smallest viable design.
6. Record meaningful decisions.

## Guardrails

- Prefer evolutionary design over replacement when practical.

## Output

Return:
- result
- evidence
- risks
- required follow-up
