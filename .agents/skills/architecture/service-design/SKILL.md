# Service Design

## Purpose

Design backend service boundaries and responsibilities.

## Procedure

1. Identify domain capability.
2. Map inputs/outputs.
3. Separate orchestration from domain rules.
4. Define failure behavior.
5. Identify transactional boundaries.

## Guardrails

- Avoid services that are merely renamed utility bags.

## Output

Return:
- result
- evidence
- risks
- required follow-up
