# Design System Review

## Purpose

Review UI work for design-system consistency.

## Procedure

1. Inspect existing primitives/tokens.
2. Check spacing/type/state conventions.
3. Find unnecessary one-off components.
4. Review dark/light themes if relevant.
5. Document new reusable pattern only when justified.

## Guardrails

- Prefer established primitives.

## Output

Return:
- result
- evidence
- risks
- required follow-up
